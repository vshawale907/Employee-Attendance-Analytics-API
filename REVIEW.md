# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | Floors elapsed minutes before comparing against 10-minute grace period (`int(elapsed / 60) > 10`). At 09:40:01 (601 seconds elapsed), `int(601/60) = 10`, then `10 > 10` is False, returning 0 late minutes instead of 10 (Rule R2). | Punch-in at 09:40:01 for shift 09:30. Returns `0` instead of `10`. | Truncate timestamp to whole seconds, check `elapsed_seconds > 600`, and calculate whole minutes as `elapsed_seconds // 60`. |
| 2 | `compute_late_minutes` (lines 33-37) | Replaces hour and minute on `punch_in` directly (`punch_in.replace(...)`), anchoring shift start in UTC instead of IST. Also fails on overnight shifts where punch-in past midnight belongs to the previous calendar day (Rule R1). | On UTC servers, shift start "09:30" is treated as 09:30 UTC (15:00 IST), miscalculating late minutes by 330 minutes. | Construct shift start as an explicit IST datetime on the shift's calendar date, convert to UTC, and compare against UTC punch-in. |
| 3 | `compute_work_hours` (lines 40-41) | Uses Python built-in `round(..., 2)` which performs round-half-to-even (banker's rounding). E.g. 0.125 hours (450s) rounds to 0.12 instead of 0.13 (Rules R4, R8). | Punch-in at 10:00:00, punch-out at 10:07:30 (450s = 0.125h). Returns `0.12` instead of `0.13`. | Used `Decimal` division quantized to two decimal places with explicit `ROUND_HALF_UP`. |
| 4 | `compute_overtime` (lines 44-48) | Does not enforce the 30-minute minimum threshold required by Rule R3. Any minutes past shift end are returned as overtime. | Punch-out 29 minutes past shift end. Returns `29` instead of `0`. | Check `elapsed_minutes >= 30`; if false, return 0. |
| 5 | `compute_overtime` (lines 44-48) | Assumes `shift_end` is always on the same calendar date (`date_str`), which is incorrect for overnight shifts (e.g. 22:00 to 06:00 where shift ends next morning). Also causes `TypeError` when subtracting offset-naive and offset-aware datetimes. | Overnight shift starting 2026-07-06 at 22:00 and ending 2026-07-07 at 06:00. Comparing against 2026-07-06 06:00 calculates over 16 hours of bogus overtime; or raises `TypeError`. | Calculate shift end on `date + 1 day` when `shift_end <= shift_start`, normalize all instants to UTC before subtraction. |
| 6 | Database Connection / Lifespan (lines 20-23) | Connects to MongoDB on module import with hardcoded fallback defaults (`os.getenv("MONGO_URI", "mongodb://localhost:27017")`). Indexes are never created at startup. | App crashes on import if Mongo is temporarily unavailable; queries perform collection scans (COLLSCAN) failing explain plan requirements. | Used FastAPI `lifespan` handler to ping DB on startup, read env vars strictly (real env wins over `.env`), and created compound indexes idempotently. |
| 7 | `GET /health` (lines 72-74) | Statically returns `{"status": "ok"}` without checking MongoDB connectivity. | Stopping MongoDB container still results in HTTP 200 from `/health`. | Execute `client.admin.command('ping')` inside `/health`; returns HTTP 503 if ping fails or times out. |
| 8 | `POST /employees` (lines 79-83) | Check-then-insert race condition: uses `find_one` then `insert_one`. Under concurrent requests with identical `emp_code`, both pass `find_one` and create duplicate employees. | Concurrent requests script creating `EMP0001` results in multiple documents with identical `emp_code`. | Created unique index on `emp_code` in MongoDB and caught `DuplicateKeyError` to return HTTP 409. |

## Examined and Decided NOT Defects

1. **Default shift times `09:30` / `18:30` in Employee model**: The schema and problem statement define standard daytime shift hours as 09:30 to 18:30. Allowing these as schema defaults is valid and convenient, provided that format validation regex (`^(?:[01]\d|2[0-3]):[0-5]\d$`) is enforced when values are provided.
2. **`history` initialized to empty list `[]` on punch-in**: Correct per DATA_MODEL and business rules; `history` is reserved strictly for audit records of manual corrections produced by the `PATCH /attendance/{emp_code}/{date}` regularization endpoint. Routine punch-in and punch-out operations must never append to `history`.
3. **`half_day` initialized to `False` on punch-in**: Correct per Rule R5; `half_day` is determined only after punch-out when total `work_hours` has been computed (`work_hours < 4.50`). Prior to punch-out, `work_hours` is `null` and `half_day` is `False`.
